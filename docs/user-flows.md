# Пользовательские сценарии QuizCraft

Документ описывает основные пользовательские потоки текущего приложения QuizCraft. Проект поддерживает загрузку TXT/DOCX/PDF, генерацию через direct/RAG, редактирование, перегенерацию одного вопроса, экспорт и проверку доступности backend/LLM-провайдера. 

## 1. Первый запуск и проверка сервисов

**Цель:** понять, готово ли приложение к генерации квизов.

1. Пользователь открывает `http://127.0.0.1:5500`.
2. Frontend загружает интерфейс и проверяет backend через `/health`.
3. Если backend доступен, приложение загружает настройки генерации и доступные форматы экспорта.
4. Приложение проверяет LLM-провайдера через health-эндпоинт backend.
5. В верхней панели отображается статус backend и провайдера.

**Исключения:**

* Если backend недоступен, генерация блокируется.
* Если LLM-провайдер недоступен, backend может работать, но генерация не запускается.

## 2. Генерация квиза из документа

**Цель:** создать новый квиз из учебного материала.

1. Пользователь загружает TXT, DOCX или PDF.
2. Пользователь выбирает количество вопросов, типы вопросов, язык, сложность, режим генерации, модель и профиль.
3. Frontend проверяет готовность backend и LLM-провайдера.
4. Frontend отправляет документ в `POST /documents`.
5. Backend проверяет файл, извлекает и нормализует текст, сохраняет запись документа.
6. Frontend отправляет параметры в `POST /documents/{document_id}/generate`.
7. Backend выбирает direct-режим или RAG, вызывает LLM-провайдера, проверяет результат и сохраняет квиз.
8. Frontend показывает готовый квиз и добавляет его в историю последних квизов.

**Исключения:**

* Если документ не выбран, отправка блокируется.
* Если не выбран тип вопроса, отправка блокируется.
* Если файл или генерация не проходят проверку, интерфейс показывает ошибку.

## 3. Генерация через RAG

**Цель:** создать квиз по длинному документу.

1. Пользователь выбирает автоматический режим или RAG.
2. Backend получает запрос генерации и определяет итоговый режим.
3. При RAG backend делит текст на фрагменты.
4. Backend получает embeddings от провайдера.
5. Система выбирает релевантные фрагменты и строит prompt.
6. LLM возвращает структурированный JSON квиза.
7. Backend проверяет и сохраняет результат.

**Исключения:**

* Если embeddings не получены, генерация завершается ошибкой.
* Если релевантный контекст не найден, backend возвращает контролируемую ошибку.

## 4. Просмотр и экспорт квиза

**Цель:** проверить результат и скачать его в нужном формате.

1. После генерации пользователь видит название, вопросы, ответы и пояснения.
2. Frontend включает кнопки экспорта на основе `/export/formats`.
3. Пользователь выбирает JSON, DOCX, PPTX, Markdown или CSV.
4. Frontend скачивает файл через `/quizzes/{quiz_id}/export/{format}`.
5. Backend загружает сохранённый квиз и формирует файл.

**Исключения:**

* Если квиз не создан или не загружен, экспорт недоступен.
* Если формат не поддерживается backend, экспорт завершается ошибкой.

## 5. Загрузка и редактирование квиза

**Цель:** изменить ранее созданный квиз.

1. Пользователь открывает редактор.
2. Пользователь вводит ID квиза или выбирает квиз из истории.
3. Frontend загружает квиз через `GET /quizzes/{quiz_id}`.
4. Пользователь редактирует название, вопросы, ответы, пары соответствия и пояснения.
5. После изменений интерфейс помечает форму как несохранённую.
6. Пользователь сохраняет изменения.
7. Frontend отправляет данные в `PUT /quizzes/{quiz_id}`.
8. Backend проверяет структуру квиза и сохраняет обновлённую версию.
9. Frontend показывает сохранённый результат.

**Исключения:**

* Если ID не указан, загрузка блокируется.
* Если квиз не найден, отображается ошибка.
* Если данные не проходят проверку, редактор показывает сообщение и оставляет возможность исправить ввод.

## 6. Перегенерация одного вопроса

**Цель:** заменить слабый вопрос без пересоздания всего квиза.

1. Пользователь открывает квиз в редакторе.
2. Пользователь нажимает перегенерацию у конкретного вопроса.
3. Frontend отправляет запрос в `POST /quizzes/{quiz_id}/questions/{question_id}/regenerate`.
4. Backend загружает квиз и исходный документ.
5. Backend применяет настройки генерации и вызывает LLM только для выбранного вопроса.
6. Backend проверяет обновлённый квиз и сохраняет его.
7. Frontend заменяет только выбранный вопрос.

**Исключения:**

* Если backend возвращает вопрос с неожиданным ID, обновление отклоняется.
* Несохранённые изменения в других вопросах остаются локально и требуют отдельного сохранения.

## 7. Настройки и история

**Цель:** не вводить одни и те же параметры заново.

1. При запуске приложение загружает сохранённые настройки генерации.
2. Пользователь создаёт квиз с выбранными параметрами.
3. Backend сохраняет настройки как значения по умолчанию.
4. Frontend сохраняет последние quiz ID в `localStorage`.

**Исключения:**

* Если сохранённых настроек нет, используются значения backend по умолчанию.
* Если история пуста, пользователь может ввести ID квиза вручную.

## 8. Копирование технических ID

**Цель:** быстро получить идентификаторы для диагностики.

1. После операций приложение показывает document ID, quiz ID и request ID.
2. Пользователь нажимает кнопку копирования.
3. Frontend копирует значение в буфер обмена.
4. Интерфейс показывает результат копирования.

**Исключение:** если доступ к clipboard API запрещён, отображается ошибка.

## 9. Смена темы интерфейса

**Цель:** изменить внешний вид без влияния на данные квиза.

1. Пользователь нажимает переключатель темы.
2. Frontend меняет режим отображения.
3. Выбранная тема сохраняется в браузере.
4. При следующем открытии применяется сохранённая тема.

## Краткая сводка

Основной поток:

`Открыть приложение → Проверить сервисы → Загрузить документ → Настроить параметры → Сгенерировать квиз → Просмотреть результат → Отредактировать или экспортировать`

Дополнительные потоки:

* `Загрузить существующий квиз → Изменить → Сохранить → Экспортировать`
* `Загрузить существующий квиз → Перегенерировать вопрос → Проверить → Сохранить или экспортировать`
* `Ошибка генерации → Показать сообщение → Вернуться к настройке`
