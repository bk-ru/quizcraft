# QuizCraft — прототип улучшенного фронтенда

Самодостаточный HTML/CSS/JS прототип. Запускается через локальный http-сервер или GitHub Pages. Бэкенд не нужен — есть мок (`mock-api.js`), который имитирует генерацию с этапами, журналом и стримом вопросов.

```bash
cd mockups/compact-workspace
python3 -m http.server 7890
# → открыть http://127.0.0.1:7890/
```

## Редактируемые демо-данные

Демо-контент вынесен в JSON-файлы, чтобы менять пример без правки JavaScript:

- `data/example-text.json` — текст, который вставляется кнопкой «Пример».
- `data/example-questions.json` — вопросы, которые мок-генератор показывает после запуска.

Минимальная структура текста:

```json
{
  "title": "Фотосинтез",
  "text": "Текст, на основе которого пользователь пробует сценарий..."
}
```

Минимальная структура вопросов:

```json
{
  "title": "Квиз по теме",
  "questions": [
    {
      "id": "q1",
      "type": "single_choice",
      "text": "Текст вопроса",
      "options": [
        { "id": "a", "text": "Правильный ответ", "correct": true },
        { "id": "b", "text": "Неверный ответ", "correct": false }
      ],
      "explanation": "Пояснение к ответу"
    }
  ]
}
```

Поддерживаемые типы: `single_choice`, `true_false`, `fill_blank`, `short_answer`, `matching`.

Для `matching` удобнее использовать `pairs`:

```json
{
  "id": "q5",
  "type": "matching",
  "text": "Сопоставьте понятия.",
  "pairs": [
    { "id": "p1", "left": "Термин", "right": "Определение" }
  ]
}
```

Если `data/example-questions.json` не загрузится или будет невалидным, мокап вернётся к встроенному случайному генератору.

## GitHub Pages

В корне репозитория добавлен workflow `.github/workflows/pages.yml`. Он публикует только каталог `mockups/compact-workspace`, поэтому на Pages открывается именно мокап, а не весь репозиторий.

В GitHub нужно включить Pages в режиме **GitHub Actions**: `Settings → Pages → Build and deployment → Source → GitHub Actions`. После push workflow задеплоит сайт и покажет публичный URL в job `deploy`.

## Что изучено в исходном репозитории

- `frontend/` — vanilla ES-модули, ~7 K строк, разделение по файлам по фичам (api, copy, theme, modal, quiz-renderer и т.д.).
- `docs/design/concepts/v2/` — мокапы целевого дизайна: тёмная тема, gradient-hero, табы paste/upload, конвейер этапов, экспорт-страница, мобильная версия.
- Расхождение: концепты опережают код. Текущий UI ближе к `v1`: одна большая форма с раскрытыми блоками, скрытая история через `<datalist>` в editor disclosure, экспорт сразу шестью кнопками без выбора содержимого, плеера/превью нет, журнал генерации виден всегда мелким шрифтом.

## Что улучшено в прототипе

### Сценарий
1. **Tabbed input** *(Файл / Текст / Ссылка)* вместо двух разнесённых форм. URL-ввод — новая ветка, которой раньше не было.
2. **Single-screen flow** — Hero/Workbench → Status → Result. Workbench не «сворачивается» полу-открытыми деталями, а заменяется. Возврат и история — отдельные переходы.
3. **Recent quizzes grid** в localStorage с превью и быстрым возвратом, вместо скрытого `datalist` для ID.
4. **Inline-editable questions**: текст и варианты — `contenteditable`, клик по варианту = переключение «правильности». Без модалок и отдельной формы.
5. **Per-question actions**: регенерация, дубликат, удаление с подтверждением через undo-stack (Ctrl+Z).
6. **Превью / play mode**: пройти квиз самому до экспорта, увидеть подсветку правильно/неправильно и пояснения.
7. **Export modal** с выбором формата (JSON / Markdown / DOCX / CSV-Forms / GIFT / QTI 2.1) **и** контента (ответы, пояснения, сложность, шаффл). Живой превью + размер.
8. **Drag-and-drop overlay** во всё окно — не только в зоне dropzone.

### Восприятие времени
9. **Smart estimate** перед запуском: токены × скорость модели × множитель RAG → строка «~ 45 сек / ~4 200 токенов».
10. **Pipeline animated** — этапы конвейера, активный пульсирует, завершённые с галочкой.
11. **Live streaming preview**: скелетон-карточки заполняются по мере прихода вопросов — пользователь видит результат раньше «100%».
12. **Журнал** — collapsible, с подсветкой временных меток / тегов / ok / warn.
13. **Орбита** вместо стандартного спиннера — лучше показывает «модель работает», не уводя внимание.

### Управление и доступность
14. **Status pill** в шапке — компактный, кликабельный, разворачивается в диагностический модал. Раньше было две «жирных» пилюли с retry-кнопками.
15. **Глобальные хоткеи** с подсказкой по `?`: `G` сгенерировать, `T` тема, `Ctrl+S` сохранить, `Ctrl+Z` undo, `Ctrl+Enter` запуск из textarea, `Esc` закрыть модал.
16. **Тема dark / light** с сохранением выбора. Светлая — бумажно-кремовая, не серая дефолтная.
17. **Reduced-motion** соблюдается — все анимации выключаются.
18. **Sticky CTA** на мобилке вместо растягивания формы по экрану.

### Типографика и визуал
19. **Fraunces** (display, заголовки/вопросы) + **Geist** (UI) + **JetBrains Mono** (метрики). Уход от дефолтного Inter.
20. **Glassmorphism + grain-grid + aurora** фон вместо плоского `--bg`. Карточки имеют общую обводку и градиент-подложку, не «рваные».
21. **Gradient text** на акценте заголовка, чтобы heading читался как product wordmark.
22. **Toggle-chips для типов вопросов** с micro-iconography (A·B·C / ● / ± / ¶ / ⇄) — заменяют чекбоксы.
23. **Slider с pill-меткой** для количества вопросов и линейкой 3/10/20/30.

## Структура файлов

```
quizcraft-prototype/
├── index.html      ← разметка, без фреймворков
├── styles.css      ← дизайн-система (1 файл, ~1.2 K строк, токены + компоненты + responsive)
├── app.js          ← state, события, рендер редактора, экспорт, плеер
├── mock-api.js     ← имитация конвейера генерации и регенерации одного вопроса
├── data/
│   ├── example-text.json
│   └── example-questions.json
└── README.md       ← этот файл
```

## Что можно перенести в продакшен сразу

- Дизайн-токены (`:root` + `[data-theme="light"]`) → заменить текущий `tokens.css`.
- Структуру flow Workbench → Status → Result → миграция `app.js` и `index.html`.
- Inline-editor вместо disclosure-формы.
- Export modal вместо отдельной полосы кнопок.
- Status pill вместо двух topbar-индикаторов.
- Хоткеи + overlay (модуль `keyboard.js` уже есть, нужны UI-надстройки).

## Чего сознательно нет в прототипе

- Реальной связки с FastAPI бэкендом — намеренно мок, чтобы открывалось без зависимостей.
- DOCX/QTI генерируются упрощённо (текстовая болванка). В проде нужны `python-docx` / `qti-py` на бэке, фронт только запрашивает blob.
- Drag-to-reorder вопросов — задел в DOM есть, нужен `Sortable.js` или нативный HTML5 DnD.
- A11y-аудит до уровня WCAG AA — стартовая база (`aria-live`, `aria-pressed`, focus-ring), но не вычитано до конца.
