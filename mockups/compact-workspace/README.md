# QuizCraft — мокап улучшенного фронтенда

Самодостаточный HTML/CSS/JS мокап. Запускается через локальный http-сервер или GitHub Pages. Бэкенд не нужен — есть мок (`mock-api.js`), который имитирует генерацию с этапами, журналом и стримом вопросов.

```bash
cd mockups/compact-workspace
python3 -m http.server 7890
# → открыть http://127.0.0.1:7890/
```

## Редактируемые демо-данные

Демо-контент вынесен в JSON-файлы, чтобы менять пример без правки JavaScript:

- `data/example-text.json` — текст, который вставляется кнопкой «Пример».
- `data/example-questions.json` — вопросы, которые мок-генератор показывает после запуска.

Минимальная структура текста:

```json
{
  "title": "Фотосинтез",
  "text": "Текст, на основе которого пользователь пробует сценарий..."
}
```

Минимальная структура вопросов:

```json
{
  "title": "Квиз по теме",
  "questions": [
    {
      "id": "q1",
      "type": "single_choice",
      "text": "Текст вопроса",
      "options": [
        { "id": "a", "text": "Правильный ответ", "correct": true },
        { "id": "b", "text": "Неверный ответ", "correct": false }
      ],
      "explanation": "Пояснение к ответу"
    }
  ]
}
```

Поддерживаемые типы: `single_choice`, `true_false`, `fill_blank`, `short_answer`, `matching`.

Для `matching` удобнее использовать `pairs`:

```json
{
  "id": "q5",
  "type": "matching",
  "text": "Сопоставьте понятия.",
  "pairs": [
    { "id": "p1", "left": "Термин", "right": "Определение" }
  ]
}
```

Если `data/example-questions.json` не загрузится или будет невалидным, мокап вернётся к встроенному случайному генератору.

## GitHub Pages

Workflow `.github/workflows/pages.yml` публикует только каталог `mockups/compact-workspace`, поэтому на Pages открывается именно мокап, а не весь репозиторий.

В GitHub нужно включить Pages в режиме **GitHub Actions**: `Settings → Pages → Build and deployment → Source → GitHub Actions`. После push workflow задеплоит сайт и покажет публичный URL в job `deploy`.

## Назначение мокапа

- Показывает компактное рабочее пространство QuizCraft для генерации квизов из текста или файла.
- Фиксирует основной путь пользователя: ввод материала → генерация → редактирование вопросов → превью → экспорт.
- Описывает визуальный язык интерфейса: тёмная и светлая тема, gradient-hero, конвейер этапов, экспорт-страница и мобильная версия.

## Что показывает мокап

### Сценарий
1. **Tabbed input** *(Файл / Текст / Ссылка)* — единая зона ввода для разных источников материала.
2. **Single-screen flow** — Hero/Workbench → Status → Result. Сценарий держит фокус на текущем шаге, а возврат и история оформлены отдельными переходами.
3. **Recent quizzes grid** в localStorage с превью и быстрым возвратом к прошлым квизам.
4. **Inline-editable questions**: текст и варианты — `contenteditable`, клик по варианту переключает «правильность».
5. **Per-question actions**: регенерация, дубликат, удаление с подтверждением через undo-stack (Ctrl+Z).
6. **Превью / play mode**: пройти квиз самому до экспорта, увидеть подсветку правильно/неправильно и пояснения.
7. **Export modal** с выбором формата (JSON / Markdown / DOCX / CSV-Forms / GIFT / QTI 2.1) **и** контента (ответы, пояснения, сложность, шаффл). Живое превью + размер.
8. **Drag-and-drop overlay** во всё окно с отдельным состоянием для прикрепления файла.

### Восприятие времени
9. **Smart estimate** перед запуском: токены × скорость модели × множитель RAG → строка «~ 45 сек / ~4 200 токенов».
10. **Pipeline animated** — этапы конвейера, активный пульсирует, завершённые с галочкой.
11. **Live streaming preview**: скелетон-карточки заполняются по мере прихода вопросов, показывая предварительный результат до завершения генерации.
12. **Журнал** — collapsible, с подсветкой временных меток / тегов / ok / warn.
13. **Орбита** — индикатор работы модели, который сохраняет ощущение активного процесса.

### Управление и доступность
14. **Status pill** в шапке — компактный, кликабельный, разворачивается в диагностический модал.
15. **Глобальные хоткеи** с подсказкой по `?`: `G` сгенерировать, `T` тема, `Ctrl+S` сохранить, `Ctrl+Z` undo, `Ctrl+Enter` запуск из textarea, `Esc` закрыть модал.
16. **Тема dark / light** с сохранением выбора. Светлая — бумажно-кремовая, не серая дефолтная.
17. **Reduced-motion** соблюдается — все анимации выключаются.
18. **Sticky CTA** на мобилке для быстрого запуска генерации.

### Типографика и визуал
19. **Fraunces** (display, заголовки/вопросы) + **Geist** (UI) + **JetBrains Mono** (метрики).
20. **Glassmorphism + grain-grid + aurora** как фоновая система. Карточки имеют общую обводку и градиент-подложку.
21. **Gradient text** на акценте заголовка, чтобы heading читался как product wordmark.
22. **Toggle-chips для типов вопросов** с micro-iconography (A·B·C / ● / ± / ¶ / ⇄).
23. **Slider с pill-меткой** для количества вопросов и линейкой 3/10/20/30.

## Проектные решения в мокапе

- Дизайн-токены для тёмной и светлой темы: `:root` + `[data-theme="light"]`.
- Структура flow: Workbench → Status → Result.
- Inline-editor для правки вопросов и вариантов прямо в карточке.
- Export modal с настройками формата и состава файла.
- Status pill с диагностикой подключения и модели.
- Хоткеи и overlay для быстрых действий.

## Технические границы мокапа

- Бэкенд представлен `mock-api.js`, поэтому мокап открывается без FastAPI и внешних зависимостей.
- DOCX/QTI генерируются упрощённо; полноценный экспорт требует серверной генерации через `python-docx` / `qti-py`.
- Drag-to-reorder вопросов требует подключения `Sortable.js` или нативной HTML5 DnD-логики.
- A11y-база есть (`aria-live`, `aria-pressed`, focus-ring); перед релизом нужен полный аудит WCAG AA.
